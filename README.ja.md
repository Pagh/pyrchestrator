# pyrchestrator

[English](README.md) · **日本語**

Python で書かれた RPA ロボットのための軽量オーケストレーターです。優先度付きのワークキュー、リトライ、ログ、スケジューリングを備え、3〜4 台のロボットを並列で動かします。

UiPath Orchestrator のようなプラットフォームのうち、ロボットを本番環境で動かし続ける部分を、仕組みから理解するためにゼロから作っています。目的はその部分を理解することで、こうしたプラットフォームと競合することではありません。

> **ステータス:** 設計段階(v0.1 前)。まだ動作するコードはありません。
> このプロジェクトが生まれた理由: [docs/ORIGIN.ja.md](docs/ORIGIN.ja.md)

---

## なぜ作るのか

ロボットのコードを書くこと自体は、手間のかからない部分です。AI の登場でさらに手軽になりました。本当にコストがかかるのは、そのロボットを何年も動かし続けることです。

- どのロボットがどの作業を取るのか、また同じ作業を二重に取らないようにするにはどうするか
- 処理の途中でロボットが落ちたらどうなるのか
- どのエラーをリトライすべきで、どのエラーはすべきでないのか
- ログ、スクリーンショット、認証情報をどこに保管するのか

このプロジェクトでは、この層を一つずつ作り直して理解します。詳しい経緯は [docs/ORIGIN.ja.md](docs/ORIGIN.ja.md) をご覧ください。

## 予定しているアーキテクチャ

```
 CLI / REST API ──► データベース (SQLite → PostgreSQL) ◄── スケジューラー
                         ▲
          アトミックな取得 │
          ┌──────────────┼──────────────┐
       Worker 1       Worker 2       Worker 3/4
          │
    robot.py は独立したプロセスで実行(タイムアウトあり、停止可能)
          │
    SDK: get_transaction() · set_status() · log() · get_asset()
```

## ロードマップ

各バージョンは単体で動作する状態にし、git タグを付けます。どのバージョンで開発が止まっても、そこまでの機能は動きます。

| バージョン | 目標 |
|---|---|
| **v0.1** | SQLite 上のキュー、アイテム追加用の CLI、アイテムを取得・処理・状態更新する Worker 1 台 |
| **v0.2** | アトミックな取得による 3〜4 台の並列 Worker。リトライ。ビジネス例外とシステム例外の区別。リースとハートビートにより、停止した Worker のアイテムをキューに戻す |
| **v0.3** | サブプロセスとして動く実際のロボット、小さな SDK、DB へのログ保存、エラー時のスクリーンショット。デモ: Playwright による [RPA Challenge](https://rpachallenge.com) |
| v0.4 | REST API(FastAPI)とシンプルな Web ダッシュボード |
| v0.5 | スケジューラー(cron)、キュートリガー、プロセス間の優先度 |
| v0.6 | 暗号化されたアセット、API キー認証、監査ログ |
| v0.7 | PostgreSQL(`FOR UPDATE SKIP LOCKED`)、Docker Compose、CI |

## UiPath Orchestrator の概念 → pyrchestrator

| UiPath Orchestrator | pyrchestrator(予定) | バージョン |
|---|---|---|
| キュー / キューアイテム | `queue` / `queue_item` テーブル | v0.1 |
| 一意の参照(Unique Reference) | キューごとに一意の `reference`(冪等性) | v0.1 |
| ビジネスルール例外 | `BusinessError`: リトライしない | v0.2 |
| システム例外 / アプリケーション例外 | `SystemError`: `max_retries` 回までリトライ | v0.2 |
| ロボット / マシン | ハートビートと処理容量を持つ Worker プロセス | v0.2 |
| プロセス / ジョブ | 登録されたロボット / 1 回の実行 | v0.3 |
| ログ | `log_entry` テーブル + スクリーンショット | v0.3 |
| トリガー(時間・キュー) | スケジューラー | v0.5 |
| アセット / 資格情報 | 暗号化された `asset` テーブル | v0.6 |

## 方針

- **コードは自分の手で書く。** AI は各フェーズの終わりにレビュー役として使い、コードの作者にはしません。
- **フレームワークより概念。** Celery、Redis、Temporal は使いません。取得、リース、リトライを自分で実装することが、このプロジェクトの目的です。
- **制限を正直に書く。** 各リリースで、まだできないことを明記します。

## 既知の制限

すべて。プロジェクトはまだ始まっていません。ロードマップをご覧ください。
